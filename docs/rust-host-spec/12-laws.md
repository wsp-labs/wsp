# 12 Laws: what checks the source, and what becomes a Rust lint

A law is a check that reads the source rather than running it. The TS repo has many; this chapter sorts them into three piles (survives as a tape or contract test, needs a Rust twin, goes with the TS code) and adds the lints the port itself needs. Every `file:line` is at `a3b870a6e`.

## Lints the port adds

12.1. Every host crate MUST build with `cargo clippy --all-targets -- -D warnings` (the daemon's CI line today, `.github/workflows/daemon.yml:68`) and these denied. The levels go once in the workspace's `[workspace.lints.clippy]` table and every member crate sets `[lints] workspace = true`; the method list cannot live in that table and goes in a `clippy.toml` at the workspace root as `disallowed-methods` (neither file exists under `daemon/` today). Measured with clippy 0.1.97 on that layout: the root `clippy.toml` applies to a member crate, `str::trim`, `str::trim_start`, `str::trim_end`, `f64::round`, `std::time::SystemTime::now`, `std::time::Instant::now`, `std::thread::sleep` and `std::process::Command::new` each fire as written, `todo!()` fires `clippy::todo`, a `RefCell` borrow held over an `.await` fires `await_holding_refcell_ref`, and an `#[allow(clippy::disallowed_methods)]` on an item silences it.
- `clippy::await_holding_refcell_ref`, so no state borrow crosses an await (rule 3.3);
- `clippy::disallowed_methods`, listing: `str::trim`, `str::trim_start`, `str::trim_end`, `str::trim_matches` (use `js_trim`, rule 8.6); `f64::round` (use `js_round`, rule 8.12); `indexmap::IndexMap::remove` and `swap_remove` (use `shift_remove`, rule 3.11); for rule 3.15, `std::time::SystemTime::now`, `std::time::Instant::now`, `std::thread::sleep`, `tokio::time::sleep`, `sleep_until`, `interval`, `timeout` and `tokio::time::Instant::now`; for rule 3.16, `uuid::Uuid::new_v4`, `uuid::Uuid::now_v7`, `rand::random`, `rand::thread_rng`, `rand::rng` and `getrandom::getrandom`; `std::process::Command::new` and `tokio::process::Command::new` outside the spawn helpers (06, 07). "Outside the clock module" (and the ids module, and the spawn helpers) is spelled as one `#[expect(clippy::disallowed_methods, reason = "...")]` on that module, never a path rule;
- `clippy::todo` outside a unit still in its `packet` or `red` state, which the unit gate enforces (13.24).

What no lint catches and review holds: the regex class `\s` and `char::is_whitespace` where JavaScript's whitespace set is meant (rule 8.6).

12.2. `cargo xtask laws` MUST check that every host crate turns on serde_json's `preserve_order` (rule 4.26), that no host crate depends on a crate in its own layer or above (rule 1.5), and that every path in `clippy.toml`'s `disallowed-methods` resolves to an item of a crate in the workspace's lock. A path to a crate that is not a dependency is silently inert: on the measured layout an `indexmap::...` entry with no `indexmap` dependency printed nothing, so a misspelled or not-yet-used path would pass every build while banning nothing.

12.3. `cargo xtask laws` MUST be one command with the shape of `pnpm check:laws` (`pre-review.sh:4-5`: "every check runs even after one fails, and any FAIL exits 1"; `fail()` at `:72` prints `FAIL  <step>: <reason>` and sets `failed=1`; no `set -e`, only `set -u` at `:14`): every law runs even after one fails, each prints `PASS`, `FAIL` or `SKIP` with its reason, and any FAIL exits 1. The TS script reports one line per step, not per law (the 28 files are one vitest call, `:313`, whose failure line names at most 5 failing tests, `:301`, with the full log kept and its path printed only on a failure, `:81`); the Rust command prints one line per law. Two TS behaviours it does not copy: when the throwaway merge with `origin/main` fails, the TS script reports the laws step as FAIL and skips the size check and the test budget without a line (`:275-284,316,328`); and a usage error exits 2 (`:27,31,115`) before any law runs.

12.4. Until cutover both run: `pnpm check:laws` for the TS tree and `cargo xtask laws` for the host's crates; `scripts/pre-review.sh` runs the second when a change touches the host's crates, as it runs `cargo fmt --check` for `daemon/` today.

12.5. A law that is retired MUST be deleted with the code it guards in the same change, its row removed from `LAWS` in `pre-review.sh`, and, when it is one of the 22, from the `LANDING` list in `packages/protocol/test/law-list.test.ts:10-33`. `law-list.test.ts` holds three things: every `LANDING` file is in `LAWS` (`:48-50`), every test that calls `holdTo(` is in `LAWS` (`:52-56`), and every `LAWS` entry exists and is listed once (`:58-60`).

12.6. A check that ran nothing MUST fail. This is new, not a property of the TS laws: only `words.test.ts` (one case, `:220`), `boat-words.test.ts` (more than 100 words, `:50`), `test-hygiene.test.ts` (more than 500 files, `:340-341`), `test-env.test.ts`, `fixture-privacy.test.ts` and `area-notes.test.ts` guard against matching nothing; the size check, the test budget, `no-separator-dots`, `harness-lines`, `app-ports`, `format` and `license` print a pass over zero files. Each twin MUST fail on zero: a unit gate with zero tapes run for its ops, a parity run with an op family with no tapes, a law that matched no files. A green result over nothing is the failure the map's research found most often (tsrs's shortcut passed the whole suite while dropping errors).

## What a twin scans

The pilot's lesson for laws: a twin that scans a different set of files than its TS law passes where the TS law would fail. Each Pile 2 twin MUST state its scan the way its TS law does, extended to `.rs` only where the table says so.
