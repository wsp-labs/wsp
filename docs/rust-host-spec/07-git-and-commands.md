# 07 Git, gh and the other programs the host runs

The behaviour nobody wrote down lives here: the exact command lines, which exit codes mean what, which output is parsed and how, and which environment each child gets. Every `file:line` is at `a3b870a6e`. Rows marked (daemon) are argv the Rust daemon builds today; the host only sends an op and reads the JSON reply, so a port of the host needs the op and the reply, and the one binary (#2450) carries the daemon's argv as they are.

## Two roads for git

Most git is the daemon's. The host runs git itself for reads on this computer, a few ref writes (`branch -D`, `update-ref`, two fetches into a named ref), the project landing's clone and patch, and the `copy` verb of the daemon binary as a child.

**The host's own road.** `gitHere(cwd, args, timeoutMs = 20_000, stdin?)` (`packages/runtime/src/machines/kinds.ts:96-99`) builds `git -C <cwd> <args...>` as text with `shellLine` and runs it on the local machine as `bash -c <text>`. `shellLine` leaves a word bare when it matches `^[A-Za-z0-9_@%+=:,./-]+$` and single-quotes it otherwise, `'` becoming `'\''` (`packages/protocol/src/shell-quote.ts:4-25`). The local machine (`packages/engine/src/local-backend.ts:84-106`) runs `runChild("bash", ["-c", cmd])` with cwd `<person home>/wsp-work` (`packages/host/src/cli/wiring.ts:64`) and the host's own `process.env` object, by reference, so the login shell's PATH that `adoptLoginPath` wrote into it reaches every git (06, rule 6.15). `gitHere` never throws on a non-zero exit: it answers `{exitCode, stdout, stderr}`.

**The daemon's road.** 33 `git.*` ops (`packages/protocol/src/wire/daemon.ts:684-870`: status, diff, discard, commit, snapshot, range, turn, push, pr, prRead, prView, runLog, prMerge, issueRead, prCheckout, prDiff, prReview, prReply, prResolve, prReact, repoRead, update, startOn, branchCompare, mergeIn, prList, checkpoint, restore, checkpointDrop, worktrees, branches, switchNew, fetchBranch), each carrying `cwd`, sent through `withDaemon(entry, work)` (`packages/runtime/src/account/channels.ts:158-168`): up the computer's link where the workspace's computer serves its daemon, else one socket opened with the workspace's daemon token, used and closed. `onThisComputer(work)` (`channels.ts:247-251`) sends the frame to this computer's daemon with `cwd` the person's home, so it runs the person's own signed-in `gh`. The daemon runs every git under `GIT_OPTIONAL_LOCKS=0 GIT_TERMINAL_PROMPT=0 LC_ALL=C` and reads exit 0 and 1 as answers (`daemon/crates/wsp-daemon/src/git.rs:88,108-116`).

7.1. Host-run git MUST be built as text with `shellLine` and run by `bash -c` through the machine's exec, as today, not as an argv array: the quoting is part of the behaviour (a word with `^{commit}`, `*` or `~` is quoted, `--` and `-C` are not), and on a box or a joined computer the same text goes over ssh or the daemon's `exec` op.

7.2. `GIT_TERMINAL_PROMPT=0` MUST be set exactly where the TS host sets it, as a text prefix before `git`: in `branchGoneAtRemote` (`packages/runtime/src/projects/folders.ts:355-357`), `gitAtLead` (`machines/sub-spawn.ts:356-359`), the branch-of-record heads (`projects/branch-of-record.ts:144`), the places setup probe (`places/setup.ts:639-640`), and the clone on this computer as `env GIT_TERMINAL_PROMPT=0 <clone line>` (`kinds.ts:157`), where the clone line is `git clone [--branch <b>] -- <remote> <dest>` for a `folder` or `git` source (`project-sources.ts:49-50`) and the git host's own `gh repo clone` or `glab` line for a github or gitlab source (the gh table below). It is NOT set on `gitHere` fetches (`projects/start-from.ts:161,174`; `folders.ts:423`). A fetch that prompts is a behaviour the port keeps and 14 lists as an after-port ticket.

7.3. Git writes on one workspace MUST run one at a time through `queued(id, work)` (`folders.ts:204-212`), and a failed one MUST NOT block the next: commit, discard, restore, merge in, update, bring back and worktree removal. Only worktree removal is host-run git (`folders.ts:217`); the others are daemon ops sent under the same chain (`workspaces.ts:764,869,880,1094`; `sessions.ts:1289`; `pull-requests.ts:291`). The key is the workspace record's id, so a project folder's record and a worktree record of the same repo do not wait for each other.

## The worktree lifecycle

The host makes and removes worktrees through the daemon binary's `copy` verb, run as a child (`packages/engine/src/copier.ts`):

| Verb | Arguments after the binary | Bound | Where |
|---|---|---|---|
| make | `copy worktree --from <repo top> --home <state folder> --project <project id> --branch <branch> [--module <json>]... [--checkpoint <ref>]` | 600 s | `copier.ts:113-114` |
| mount overlays again | `copy worktree-mount --from <top> --home <state folder> --path <worktree>` | 30 s | `copier.ts:117` |
| forget a project's frozen copies | `copy worktree-forget --from <top> --home <state folder> --project <id>` | 600 s | `copier.ts:121` |

Each `--module` is `JSON.stringify` of `{id, lockfiles, carry, never, installed?}` for every ecosystem the catalog knows (`folders.ts:17`).

7.6. The `copy` verb's answer MUST be read as the TS host reads it (`copier.ts:63-106`): exit 0 with one JSON line on stdout (`WorktreeReport {path, branch, made, carried, plain?, overlaid?, fresh, modules[], ms}` or `{path, rescued?}`, held by its zod schema, which strips unknown keys and takes any key order; anything else is `the <what> verb answered something this host does not read: <first 200 units of the trimmed stdout>`, or `nothing at all` for an empty one); exit 1 is a refusal whose sentence is the last line of the trimmed stderr, or of the trimmed stdout when stderr is blank (an exit 1 with both blank refuses with the empty sentence: `"".split("\n").at(-1)` is `""`, so the `the copy failed and said nothing` fallback at `:71` is never reached, and the port keeps the empty sentence); any other exit (2 usage, 124 timeout, 127 not startable, -1 a signal) is `the daemon's copy verb failed (exit N); the host log has its output` (`protocol/src/words/units.ts:216`), with `console.warn("<binary> copy: <output>")` logged only when the output is not blank (`:66-68`). For a make, in order: no copier refuses with `NO_COPIER_HERE` (kind `invalid`); then the version check, `local.hereDaemon.version()` (`cli/wiring.ts:138`), which starts this computer's daemon as a side effect and refuses with `this computer's wsp daemon is version N and this wsp needs M; <fix> stages the right one` (`units.ts:211`) when it is older than `DAEMON_VERSION` (`folders.ts:77-81`); it is skipped when no local daemon is wired, and remove and mount run no version check. The verb runs with the host's own cwd and `process.env` (`copier.ts:91-126` pass neither), not `wsp-work`.

What the daemon decides when it makes a worktree (daemon, `daemon/crates/wsp-runtime/src/copy_road/branch.rs:66-213,449-513`): the branch name must pass `check-ref-format refs/heads/<b>` and not start with `-` (an empty name refuses with ` is not a name git takes for a branch`, `words.rs:456-457`, exit 1); the path is `<root>/<project id>/<branch with every character outside [A-Za-z0-9._-] as ->`, then `-2`, `-3` up to `-999` on a taken name (`for n in 1..1000`, `:465-475`; past that the refusal says "a thousand worktrees"), folder made 0700; `<root>` is `<state folder>/worktrees` when the state folder and the repo share a volume, else `<repo volume's mount point>/.wsp/worktrees`; an existing branch is checked out as it stands, a missing one is made at the repo top's `HEAD`; a branch already checked out in a worktree that is not prunable answers that worktree with `fresh: false` (`:90-108`), and one in a prunable worktree it made is removed with `git worktree remove` and made again (`:109-113`). A fork (`--checkpoint`) refuses a branch that already exists (`:201-205`: `the branch X already exists, so no worktree was made; a fork makes a new branch, so name one that is not there yet`) and starts at `<checkpoint>^` when it resolves, else at the folder's `HEAD` (`:209-211`). The verb's own git reads are bounded at 15 s and writes at 300 s (`copy_road/rules.rs:18,24`). The host's record name for a taken name is `<name> 2` with a space (`takenNameAfter`, `protocol/src/start.ts:189-192`); the daemon's folder is `<name>-2`.

The host's side, in order (`folders.ts:72-264`):

7.7. `folderFor` (`folders.ts:154-158`) and its `placeFor` (`:159-200`) MUST refuse in this order: a guest naming a workspace (`guestNamesWorkspaceLine`, usage, `:163`); a caller held elsewhere (`elsewhereRefusal`, `:169-170`); a project the resolve does not find (`no project "<ref>"; wsp add <folder> records one`, not-found, `:171`); no project named (`NAME_A_PROJECT_LINE`, `name the project the thread runs in`, usage, `:172`); a project not on this computer (`notOnThisComputerLine`, usage, `:174`); then, only when picks were named, `picksHold` (`:175`), which can make and store the project folder's record, write the roots file and emit `workspace.created` before any later refusal; a branch and a folder together (`BRANCH_OR_CWD_LINE`, `name a branch or a folder, not both`, usage, `:177`); a branch on a computer that is not a copying kind (`placeBranchLine`, usage, `:181`); a folder outside the project (`cwdOutsideLine`, usage, `:183,191`); a project with no repo top (`noBranchesLine`, `<project> is not a git repo, so it has no branches`, usage, `:197`). A branch equal to the one checked out in the asking thread's own folder answers that folder, and with no asking thread a branch equal to the project folder's answers the project folder, no worktree (`:198`). `sessions.start` refuses a `workspaceId` with a `branch` before any of these (`BRANCH_ON_A_THREAD_LINE`, usage, `serve-start.ts:39`).

7.8. `worktreeFolder` (`folders.ts:72-90`) MUST make one worktree at a time per `<project id>\0<branch>` through `ctx.oneFolder` (`machines/create.ts:286-292`), which is single-flight, not a lock: a second caller while one is in flight gets the first caller's promise and its record, its own `parent`, `madeFor` and checkpoint are dropped, and a failure rejects both. The setup commands run inside that slot (`folders.ts:85-88`), so a second ask waits up to 180 s a command. It MUST answer the project folder when the report's path is the repo top, and otherwise MUST record the worktree through `worktreeRecordAt` and, when the report says `fresh`, run the setup commands (7.11).

7.9. Every worktree record MUST be made by `worktreeRecordAt(project, tree, parent?)` (`folders.ts:140-149`; trap #1607): an existing record of the same path has its worktree rewritten to exactly `{path, made: was.made || tree.made, branch?, madeFor?: was.madeFor}`, which clears `settled`, `kept`, `removeFailed` and `gone` and keeps the OLD `madeFor`; a new one is `recordFolder` (`folders.ts:28-62`: id `ws_<8 hex>`, name `takenNameAfter(project.name + "@" + branch)`, then `writeDaemonRoots`, then the sweep armed if `made`, then `workspace.created`). A thread's own tree admits a worktree record whose `madeFor` is its root thread (`account/rules.ts:65-73`), so a record made any other way locks its thread out.

7.10. A worktree record with `made: false` (one the person made with plain `git worktree add`, `folders.ts:187-195`) MUST never be removed by wsp. The verb refuses it with `wsp made no worktree for <branch>; git worktree remove takes one wsp did not make` (kind `invalid`, `workspaces.ts:843`); the same sentence thrown inside `removeWorktree` (`folders.ts:221`, reached from the sweep and a thread's end) is a plain error with no kind, class 1.

7.11. A fresh worktree's setup MUST run on the local machine as `cd <folder> && <command>`, each module's `rebuild` line and then the project's `afterWorktree`, with 180 s each and an empty stdin so nothing waits on a prompt; exit 124 reads "was stopped after 3 minutes"; each start and failure is a `host.notice` event; the thread starts anyway, and its first line carries `worktreeSetupLine` (`folders.ts:91-126`).

7.12. The `worktree.remove` verb (`workspaces.ts:832-846`) MUST check in this order: resolve the project (not-found); no repo top (`noBranchesLine`, usage); find the record, one with `gone !== true` whose path is the `git worktree list` path of the branch when git holds the branch, else whose `worktree.branch` is the branch; `refuseRelayed`; not made (`notMadeWorktreeLine`, invalid); `force` from a thread's own token (`WORKTREE_FORCE_LINE`, `only the person removes a worktree over files no commit holds; commit them, or ask them to remove it`, usage); then `removeWorktree`. `removeWorktree` (`folders.ts:216-264`), under `queued`, MUST refuse in this order: no `made` record or no repo top (`notMadeWorktreeLine`, no kind); no copier (`NO_COPIER_HERE`); a turn running there and not ending (`a thread is working in that worktree; let its turn end or stop it first`, kind `conflict`); uncommitted files and not forced (`that worktree has N file(s) not committed; ...`, kind `conflict`, from `git status --porcelain`). `check: true` stops after the refusals. Then `copy worktree-remove`, run only when the folder still exists (`existsSync(tree.path)`; a folder already gone runs no verb), then `worktreeGone`: a record no thread names is dropped; one a thread names keeps `{path, made, branch?, madeFor?, settled, gone: true}`, in that key order (`folders.ts:262`), and its threads run on in the project folder.

7.13. The sweep (`folders.ts:274-358`) MUST be armed only while some worktree has `made && !gone`, run 10 minutes after it is armed and again 10 minutes after each pass ends (re-armed in the pass's `finally`, so the period is 10 minutes plus the pass), and look at every such worktree in each pass, one after another (`:298-304`). A worktree is removed only when it is settled (its pull request merged or closed, read with `readPullRequest(entry, true)`, or its branch gone at the remote by 7.4), settled at least 6 hours ago, no turn runs there, and `git status --porcelain` shows nothing. A project with no remote (`project.remote === ""`) never settles (`:338`), so its worktrees are removed only when their folder is gone (`:310`). A clean settled worktree is removed at any age; otherwise `keep()` (`:315-322`) records why (`a thread is running`, `N file(s) not committed`, the removal's last line in `removeFailed`), and once `settled.at` is 7 days old it adds `kept: "kept 7 days; remove it by hand"` and the sweep leaves it alone. `kept` is never cleared when its reason goes away, so `kept` and `removeFailed` can stand together until the record is rewritten (7.9) or removed. `keep()` skips the write when `JSON.stringify(next) === JSON.stringify(now)`, a test that depends on key order; the port compares the values (rule 7.30 gives the order).

7.14. `writeDaemonRoots(entry, strict)` (`machines/daemon.ts:88-107`) MUST write the whole roots file from every live workspace whose `machineId` is the entry's (each one's `projectHeld(project).path`, then its checkout, then `record.landed[]`, through a `Set` that keeps the first occurrence, in `live` insertion order, `:101`), one write per machine at a time, as four lines joined with `\n`: `next='<path>.next.'$$`, `mkdir -p '<dir>'`, `printf '%s\n' '<root>'... > "$next"`, `mv -f "$next" '<path>'` (`packages/runtime/src/daemon-roots.ts:10-17`). With no roots the `printf` writes one empty line. It writes nothing once the state is closed (`daemon.ts:93`), or for a workspace its computer serves when its kind does not run in a folder (`:96`). A daemon op whose `cwd` is outside the person's home and not in the file is refused, and worktrees live under the state folder (trap #1607, #1645, #1774). Failures warn unless `strict` (a project add).

## Merge, merge in, bring back

7.15. `wsp merge` (`projects/workspaces.ts:1033-1058`) MUST use the pull request fact the host holds, however old, and read only when it holds none: `isPullRequestFact(entry.pr) ? entry.pr : await ctx.readPullRequest(entry, false)`, and that unforced read can itself answer from the 10 s hold or the no-pull-request memo (`pull-requests.ts:105,110`). A fresh read would hand the head guard whatever an agent pushed since the person looked (runtime invariant 4). It checks in this order: `spawnGuard("merge")` for a thread's own token (`this request came out of <thread at place>, and a thread may only <acts>, never merge`, usage, `account/rules.ts:290-300`); the workspace (`no such workspace: <id>`, not-found); a pull request fact (none: a kept record that is not open gives `notOpenRefusal`, else `<label> has no pull request: push its branch and open one with gh pr create first`; a project with no remote answers `entry.pr` with no read, `pull-requests.ts:114`); `fact.state !== "open"` (`#<n> is <state>, so there is nothing to merge`); the repo's merge settings through this computer's daemon (`git.repoRead`, held 1 hour per remote); a method the repo does not allow (`the repository does not allow a <m> merge; it allows <list>`; a missing method is the repo's default); `whenChecksPass` on a repo without auto-merge (`AUTO_MERGE_OFF_LINE`). Then it sends `git.prMerge {cwd: <person home>, remote, number, method, auto, headOid: head ?? fact.headOid}` through `onThisComputer`, drops the page cache for that pull request, forces one read (`readPullRequest(entry, true)`) and answers `{number, method, merged, autoArmed}`. Only the app sends `head`; the schema refuses `""` (`z.string().min(1)`, `protocol/src/wire/runtime.ts:360`). The daemon runs `gh pr merge <n> -R <owner/repo> --merge|--squash|--rebase [--auto] --match-head-commit <headOid>` (daemon, `hosts/github.rs:1157-1164`), then `gh pr view <n> -R <repo> --json state,autoMergeRequest` (`hosts/mod.rs:393-409`), reading `merged = !auto, autoArmed = auto` when that view fails; a refused merge says `the merge was refused: <last non-blank line>` (`wsp-frames/src/words.rs:487`). With no daemon on this computer `onThisComputer` throws `this host runs no daemon on this computer` with no kind (`channels.ts:248`); `merge` does not reword a `no-host-cli` refusal as `postAsPerson` does, so the daemon's own sentence reaches the client.

7.16. `wsp merge in` (`workspaces.ts:1067-1105`) MUST refuse, in order: `spawnGuard("merge_in")`; the workspace (not-found); a thread merging into a workspace it does not run on (`thread <w> may merge a child only into its own folder`); a child that is not the lead's (`<child> is not a child of <lead>; a lead merges only its own children`, kind `invalid`, `machines/boot.ts:646`); a lead with a turn running in any thread but the asking one (`<lead> has a turn running in thread <ids>; merge once it ends, or from inside that turn`, trap #1476); a blocked copy; a child on no branch or on `(detached)` (`<child> is on no branch, so there is nothing to merge from it`); with no remote host on the project, a side that is not local (`noRemoteForTreeLine`), the merge then reading the child's folder. Every refusal but the not-found and `invalid` ones is a plain error with no kind (class 1). The host runs no git for checkpoints. It sends (`threads/threads.ts:963-1142`; `threads/sessions.ts:1264-1396`; `folders.ts:242-248`):

Rewind (`sessions.ts:1264-1396`) MUST check in this order: the thread (`no thread <first 8 units of the id>`, not-found); any row of the thread running (`REWIND_WORKING_LINE`, conflict); then `ctx.reapKept(threadId)` runs, a side effect before every later refusal; a child running (`rewindChildrenLine`, conflict). An undo then refuses: no earlier rewind (`REWIND_NO_UNDO_LINE`), `SUB_TURN_GONE_LINE`, another thread's turn in the folder (`rewindBesideLine`). A plain rewind refuses: the turn not found (`no turn <id> on thread <w>`, not-found; a missing `turnId` reads as index -1 and prints an empty id), `SUB_TURN_GONE_LINE`, the latest turn (`REWIND_LATEST_LINE`), a copied thread (`REWIND_COPIED_LINE`), files asked with no checkpoint ref (`REWIND_NO_CHECKPOINT_LINE`), then a harness that cannot cut or no anchor (`rewindKeptLine`, `rewindNoAnchorLine`). On a plain rewind a folder another thread is working in is not a refusal: files are quietly not moved and the answer carries `kept: REWIND_SHARED_LINE`, which refuses only when the conversation cannot be cut either. The files are put back from the `before` ref only when the revert or fork throws (`putBack`); when the harness answers with a `kept` reason, the files stay moved, `record.rewound` is stored, and the call throws `rewindKeptLine(why, true)`. The answer is `{turns, files?, kept?}`, an undo's `{turns: 0, files}`. The daemon keeps the newest 100 checkpoint refs per thread under `refs/wsp/checkpoints/<scope>/<thread>/<turn>`, counting the `-before-<ms>` refs a restore writes, ordered by `creatordate`, pruned when a checkpoint changed something and on every restore (daemon, `git/checkpoint.rs:24,46-48,105-113`); a thread, turn or scope outside `[A-Za-z0-9_-]{1,100}` is refused with `a checkpoint's <what> must be one plain name, got "<id>"` (`wsp-frames/src/checkpoint.rs:37-39`).

The frames the host sends to a daemon for this chapter MUST keep these key orders (the channel appends `id` last, `{...frame, id}`, `runtime/src/daemon-channel.ts:96`; a held reach writes `{...params, id, op}`, `reach.ts:102`): `git.prMerge {op, cwd, remote, number, method, auto, headOid}`; `git.repoRead {op, cwd, remote}`; `git.mergeIn {op, cwd, branch, from?}`; `git.push {op, cwd, base?}`; `git.pr {op, cwd, base?, title?, body?}`; `git.checkpoint {op, cwd, thread, turn, scope}`; `git.snapshot {op, cwd}`; `git.turn {op, cwd, from, to}`; `git.restore {op, cwd, checkpoint, scope}`; `git.checkpointDrop {op, cwd, scope, thread}`; `git.prRead {op, cwd, remote, number | branch, seen?}`; `git.prView {op, cwd, remote, number}`; `git.prDiff {op, cwd, remote, number, maxBytes}`; `git.runLog {op, cwd, remote, runId, jobId}`; `git.prReply {op, cwd, remote, number, replyTo?, threadId?, body}`; `git.prResolve {op, cwd, remote, number, threadId, resolved}`; `git.prReact {op, cwd, remote, number, subject, content, on}`.

7.32. A child's timeout MUST end it the way its helper does (06's helper table has the codes; these are the parts this chapter's rows lean on):
- `runChild` (`engine/src/child-exec.ts:33-150`), behind `gitHere`, the copy verb, setup, ssh and the clone: spawned detached; at the deadline `SIGKILL` to the whole group, no `SIGTERM` first and no grace; the answer is exit 124 with all the stdout and stderr read so far, uncapped; each chunk is decoded alone (`toString("utf8")`), so a character split between two chunks reads as U+FFFD in each half; the timer is cleared on the child's `exit`, then the answer waits for the pipes to close, or 200 ms of quiet (`DRAIN_MS`), or 1 s at most (`DRAIN_CAP_MS`), and drops later output; a spawn error is exit 127 with the error's message appended to stderr; a signal with no timeout is -1; a descendant that made its own session survives the kill; no `timeoutMs` means no deadline.
- `execFile` rows (`recipe-options.ts:145,151`, `channels.ts:914`, the broker's `gh`, `lsof`, `security`): node's `SIGTERM` to the direct child only, no escalation; node's default `maxBuffer` of 1 MiB unless the row names one, and a run past it fails with its stdout cut; the broker's reads report exit 1 on a timeout or an overflow (`error.code` is null or a string, `server-broker.ts:109-114`); `spawnSync` with a timeout answers `status === null`, which `channels.ts:914` reads as `""`.
- `execFile` with no timeout (`ps`, `ssh-keygen` generate, the `tar` pack) waits as long as the child runs.

7.33. A host stop MUST leave these as the TS does (`runtime/src/runtime.ts:1225-1291`): the sweep's timer is cancelled (`sweepStopped = true`, the cancel function called) and a pass already running is awaited, which can be several `copy worktree-remove` runs of up to 600 s each, as is `copiesMoving`; a `copy` verb or setup command a request started is neither awaited nor killed, leads its own group, outlives the host and loses its deadline with the host's timer; every pull request timer is cancelled (`entry.prPoll?.()`), and a read in flight is neither awaited nor aborted (its failure re-arms an unref'd timer after the close, which nothing observes; after the port); the broker's stop bumps a counter and closes (`server-broker.ts:283-289`) without killing a `gh auth token` in flight; cloudflared gets `SIGTERM` and an unbounded wait with no `SIGKILL` (`connector.ts:206-224`); the ssh forward gets `stdin.end()` and `SIGTERM` to the one child (`ssh-backend.ts:353-357`); an ssh master stays up 60 s (`ControlPersist=60`); a running turn is not touched (rule 6.16).

7.34. What survives a host restart MUST be what the TS stores, and nothing it keeps only in memory:
- Stored with the workspace record (`ctx.persist`): the whole `worktree` object, `settled` as `{at, why}` with `at` milliseconds since the epoch (`pr.mergedAt ?? now`, `pr.closedAt ?? now`, or the moment it was first seen settled), so the 6-hour and 7-day clocks run across a restart; `record.pr` (`number, url, state, base, branch, mergedAt | closedAt, checks` once settled), `record.prSent`, `record.branchThreads`; `threadRecords[...].rewound` (cleared when the next turn in that folder ends, `turns.ts:116-123`); a session row's launch `snapshot`; `session.checkpoint` events in the transcript; the checkpoint refs in the repo.
- Memory only, gone at a restart: the pull request cache (`pr:` facts and `page:` entries, `memoryGitHubCache()`; no host wiring passes another), the rate-limit holds, the repo merge settings, `entry.pr`, the no-pull-request memo, the poll timers and the read in flight; the broker's token and login (`credentials.ts`: held in memory only); `queued`, `oneFolder` and the roots-file writers; the worktree setup line a thread's first line was to carry (`folders.ts:93`); every bus event.
- At start: the sweep is re-armed at boot when some live record has a made worktree not gone (`machines/boot.ts:616`), its first pass 10 minutes later, not at boot; rows with a launch `snapshot` and no recorded changes have their changes read again (`boot.ts:500-516`); no pull request timer is armed until a read runs (a checkout read, a turn's end, bring back, merge, fix or update) and `takePullRequest` arms one; an open kept `record.pr` is then read by number with no `seen` tag, a full read; a `connector.pid` left by a crash is stopped (rule 9.21).

7.35. The snapshot and checkpoint replies MUST be read as the TS reads them: `git.snapshot`'s commit is `String(reply.commit)` (`threads.ts:1071`), so a missing field would be the text `undefined` (the daemon always sends `commit`, `GitSnapshotReply`; a port reads a missing or empty one as none and notes it); the end snapshot races 3,000 ms (`turnSnapshotMs` overrides it) and the late call is not cancelled; the launch snapshot is awaited, holding the launch up to 3 s, unless the adapter `waitsForPrompt` (`sessions.ts:703-706`); a `git.turn` reply that fails `GitDiffReply` records nothing, an empty `files` and empty `moved` records nothing, and an empty `files` with some `moved` records `session.changes` with `files: []`; `git.restore`'s `files` is `Number(reply.files ?? 0)`. `git.checkpoint`, `git.snapshot` and `git.turn` have no host-side deadline, only the channel's connect bound of 15 s, so a daemon that never answers holds them until the socket closes (`connection lost`, no kind); `dropCheckpoints` waits for a checkpoint still landing first (`folders.ts:243`), so a hung one holds a thread's delete.

7.36. The broker's and the branch-of-record's `gh` reads MUST treat empty and odd output as the TS does: `gh auth token` printing nothing or blank, or exiting non-zero, is no token and is not held, and a token already held is not cleared, only left to age out of its 5 minutes (`credentials.ts:88-93`); `gh auth status` reads only `hosts["github.com"][0]`, and non-JSON, a missing entry, `state !== "success"` or a non-string `login` is none; `gh api repos/<r> --jq .id` with empty output is `Number("")`, 0, refused by `id > 0` (`server-broker.ts:103-104`); a branch-of-record read with empty output splits to `[""]` and refuses with `no repository id in ""`, only one trailing `\r?\n` is cut, and a non-zero exit or a timeout refuses with `branchOfRecordUnreadRefusal(repo, <stderr's last line> ?? "gh exited <n>")`.

7.37. `ps` lines MUST be split with `row.trim().split(/\s+/)`; in `treeWork` a short row reads its missing columns as `Number("")`, 0, and a row with no pid is skipped; `groupRows` drops a row whose numbers are not safe integers; the CPU column is `psCpuSeconds` (`protocol/src/ps-time.ts:10`: `[dd-]hh:mm:ss`, fractions allowed, a non-finite reading 0); an `etime` with fewer than two `:` parts is none.

7.38. The pull request caches MUST keep their lifetimes: `pr:` facts never expire and grow with the pull requests read; `page:` entries expire 60 s after they are written (`clock.schedule`) and are dropped by `postAsPerson` and by a merge (`pull-requests.ts:68,135`). cloudflared restarts 2 s after an exit, the wait doubling to 30 s and never resetting after a healthy run (2, 4, 8, 16, 30, 30, ...; `connector.ts:137,147,185-197`); a spawn `error` is logged and starts nothing.

Why no tape for the rest: every rule past a project lookup needs a project, and a project needs `projects.add`, whose reply carries a random `pr_<8 hex>` id and a `createdAt` stamp that the checker does not normalize (it normalizes UUIDs, the version and the temp folder). A worktree, a merge or a checkpoint needs a git repo in the temp folder, and a tape's `in` frames cannot name that folder (`~` works and resolves to `<tmp>/home`, which is no repo, and no op makes one).
