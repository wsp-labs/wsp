## What it does
What one word to `wsp add` names and the source record it becomes, what a project is called and where its checkout sits, which repo addresses this computer clones and what a failed clone says, and the fixed lines of adding, starting, deleting and removing. It also holds the one reading of a computer id for its workspace kind, where a workspace of a project lands, and what a computer is called in a row.

## Behaviour
1. `source_kind(word)`, in order: a word starting "/", "~" or "." is folder; `github.com/<a>/<b>` or `gitlab.com/<a>/<b>` with no further "/" is that host; a word holding "://", starting `<user>@<host>:` or ending ".git" is git; `<user>@<host>` is computer; `<owner>/<repo>` is github; anything else, "" included, is an Err carrying ADD_FORMS_LINE (projects.ts:44-55).
2. `source_word`: the folder's path, the git url, else the repo (:64-67). `project_name_of`: a folder's `folder_name`; else the source word less trailing "/"s, its last part split on "/" or ":", one trailing ".git" off (:70-75). `project_path_on`: a folder's path; no home is an Err "<name> is a repo, and that computer holds no checkout of its own to put one in"; else `<home>/<name>`, joined as is (:82-86). `project_source_of`: folder keeps `folder_path`, else the word; git keeps the word as url; github and gitlab keep the word less a leading `github.com/` or `gitlab.com/`, then less one trailing ".git", under the kind given (:90-96).
3. `added_project_line` is `added_project_on(project, computer_named(..))` (:20-22). `added_project_on`: "<name> <id>: <source word> on <computer>, at <path>", plus, where `kind_for_computer(project.computer)` copies its folder (the computer the app runs on alone), a second line `open a thread on it with: wsp run <shell_quote(name)> "<message>"` (:27-30). `adding_project_line`: "<name> from <source word>." with ", nothing seeded" before the dot when not seeding (:36-38).
4. `clone_url_refusal(word)`, in order, each failure the one sentence "<word> is not a repo address wsp clones; give its https or ssh url, or owner/repo": any whitespace or a leading "-"; a word `source_kind` refuses; github and gitlab pass where the word less its host prefix matches OWNER_REPO; any kind but git fails; git's scp form (SCP_FORM) passes; then `new URL(word)` must parse, the scheme must be https or ssh, no password, no login on https, a login must match CLONE_USER, the host must match CLONE_HOST and the path must be longer than one unit (:127-160). None is accepted.
5. `clone_failed_line(said)`: the last part of `said` (trimEnd, split on "\n", trimmed); "" reads "the clone failed and said nothing"; where SIGN_IN_FAILURE matches anywhere in `said` (case-insensitive) the line gains "; sign in with gh auth login, or use the repo's ssh url" (:164-171).
6. `clone_on_machine_failed_line(o)`, in order: the first `remote: wsp: ` line's rest, trimmed, reads "the clone of <repo> on <on> failed: <it>"; else `last_line(said)` (base.ts:59-63: the last non-blank line split on `\r?\n`, whitespace runs as one space, trimmed) not starting "Cloning into " reads "failed: <line>"; else exit 124 (EXEC_DEADLINE_EXIT) reads "did not finish in <js_round(limit_ms / 60000)> minutes, and git said nothing past its start"; else "ended with exit <code>, and git said nothing past its start" (:176-184).

The add, clone and start refusals are fixed sentences with their arguments in place (:100-122, :189-224): `same_source_refusal`, `no_computer_for_source_line` (computers joined " | ", the --on clause gone for none), `clone_into_needed`, `clone_into_taken_line`, `clone_into_file_line` (no free folder reads "pick a folder to clone the repo in"), `into_is_here_line`, `seed_choice_needed`, `not_on_this_computer_line`, `child_on_another_computer_line`, `place_login_not_root_line`, `place_branch_line`, `cwd_outside_line`, `no_cwd_line`.

## Edge cases
- `source_kind("gitlab.com/thing")` is Github (the owner/repo form); `source_kind("github.com/a/b/c")` and `source_kind("")` are Err; `source_kind("gitlab.com/a/b.git")` is Gitlab, the host read before ".git".
- `project_name_of` of git "a/b.git.git" is "b.git", of "git@h:repo.git" is "repo"; of the folder "/" is "".
- `clone_url_refusal`: "HTTPS://GitHub.com/a/b" and "https://github.com:443/a" pass; "https://bücher.example/a" passes (the host maps to xn--bcher-kva.example) while "ssh://bücher.example/a" is refused (an ssh host stays percent-encoded); "https://github.com/" is refused (path "/"); "a.git" is refused (no URL parses).
- `clone_failed_line("bash: git: command not found\n")` carries the sign-in clause; `clone_failed_line("  \n\n")` is "the clone failed and said nothing"; U+212A (Kelvin sign) does not match "k" in SIGN_IN_FAILURE.
- `clone_on_machine_failed_line`: limit 150 000 ms reads "3 minutes" (`js_round(2.5)`), 90 000 reads "2 minutes"; said "remote: wsp:  \nerror: 403" ends "failed: " with nothing after; "remote: wsp: a\rb" reads "a", since `$` stops at "\r".
- `home_shortened("/root/x", Some("/root/"))` is "/root/x"; with `Some("")` it is "~/root/x".
- `project_in_use_refusal(name, [])` reads "<name> has workspaces standing on it: ; delete their threads first".

## Behaviour nobody wrote down
- Rule 8.6: `trim`, `trimEnd` and `\s` are JavaScript's whitespace (`clone_failed_line`, `last_line`, the whitespace refusal and SCP_FORM of `clone_url_refusal`).
- Rule 8.7: every regex is ported by hand; `\w` is ASCII; SIGN_IN_FAILURE's `/i` has no u flag, so only ASCII letters fold (the Kelvin sign and long s match nothing), unlike the regex crate's Unicode `(?i)`; the multiline `$` and `.` treat "\r", U+2028 and U+2029 as line ends.
- Rules 8.11 and 8.12: every number in a sentence (threads, files, copies, a pull request number, an exit code, minutes) is `js::number_string`; the clone minutes round with `js_round`.
- `new URL` is the WHATWG parser: scheme lowercased; an https host lowercased and IDNA-mapped, an ssh host opaque and percent-encoded; a port is not part of the host; an ssh path may be "", an https path is at least "/". The crate carries no url dependency.
- `JSON.stringify(ref)` matches `serde_json::to_string` for every Rust string (both escape control characters as `\uXXXX` with lowercase hex, neither escapes U+2028).

## Tapes
`wsp add` and the `projects_add` tool (the adding line, the added line, the clone refusals and failures); `wsp run` and the start refusals; `wsp delete`, `wsp forget` and `wsp worktree remove` lines and refusals; `wsp projects remove`; the first message of a thread in a new worktree; the computer column of `wsp projects` and `wsp ls`.

## Decisions
1. The two TS throws are `Err(HostError)`: `source_kind` carries ADD_FORMS_LINE, `project_path_on` the repo sentence, both plain errors with no kind stamped.
2. `ReadonlyMap<string, string> | undefined` is `Option<&IndexMap<String, String>>`; the platform union is `&words::computer::Platform`; a `readonly string[]` is `&[impl AsRef<str>]`; `projects | undefined` is `Option<&[WorkspaceProject]>`.
3. The source kind union is `SourceKind`; `project_source_of` takes `&SourceKind` and is never handed Computer.
4. Object parameters become arguments or structs: `CloneFailed` (exit code `i32`, limit `f64`), `thread_deleted_line(thread_id, worktree, threads)`, `lands_on(computer, place_id, place_name)`, `bare_folder(kind, holds_thread)` taking the record's own kind.
5. Defaults become Options: `kind_for_computer(computer, joined: Option<bool>)`, `copy_takes_none(.., computer: Option<&str>)`.
6. `WorktreeCommandEnd` is an enum (Exited, Stopped); `WorkspaceLands` an enum serialised under the tag `at`; `cloud_project_refusal` answers `place_word::RefusalHalves`.
7. PR_BEHIND_WORDS and OLD_COPY_WORDS are modules: fixed words are constants, sentences functions; a TS `number` argument is `f64`.

## After the port
- SIGN_IN_FAILURE's "not found" matches any "not found", so "bash: git: command not found" or a missing branch gains the sign-in clause.
- A `remote: wsp: ` line holding only spaces ends the clone sentence "failed: " with nothing after it.
- `source_kind("gitlab.com/thing")` reads as a github repo, and `project_source_of` then keeps repo "thing"; `clone_url_refusal` refuses it, but a road that skips that check records it.
