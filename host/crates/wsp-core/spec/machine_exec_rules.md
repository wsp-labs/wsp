## What it does
The rules both turn roads (this computer's and a machine's) share: the one rule that cuts a turn (`turn_cut`), the
idle clock the rule reads (`turn_activity`), when the turn's process tree is worth reading (`reads_work`), the two awk
programs a guest runs to read its run's tree, and `LineCut`, which turns a run's log bytes into lines. No I/O except the
awk tests, which run the programs through the awks this computer has.

## Behaviour
1. `turn_cut(limits, elapsed, quiet)`: `elapsed >= deadline` is the wall cut, else `quiet >= idle` the idle cut, else
   `None` (machine-exec.ts:105-108). The error's message is `turn_cut_line(rule, elapsed, limit)` with the limit that
   rule read; its kind is `Other`. Wall wins when both hold. Limits are `f64`; `INFINITY` never cuts.
2. `turn_activity(started)` (machine-exec.ts:134-155): `quiet_ms(now) = now - active_at`; `touch(at)` sets
   `active_at = at` even when `at` is earlier (no max); `hold(ms)` adds `ms` to `active_at`; `read(ticks, at)`: with no
   base, or `ticks` below the base's, the reading becomes the base and nothing else moves; otherwise when
   `ticks - base.ticks >= max(1, TURN_WORK_TICKS_PER_S * (at - base.at) / 1000)` (5 ticks a second, float division)
   the clock moves (`active_at = at`) and the reading becomes the base; below that floor nothing changes, the base
   included.
3. `reads_work(idle, quiet) = idle.is_finite() && quiet >= idle / 2` (machine-exec.ts:161-163). NaN reads false.
4. `TREE_WORK_AWK` and `LEFTOVERS_AWK` are the TS strings byte for byte (machine-exec.ts:178-189), generated by script
   from the TS, never retyped. The tree program counts, for every `/proc/<pid>/stat` named on its command line whose
   parent chain (up to 64 steps) reaches `p` or whose group is `p`, fields 14 to 17 (utime, stime, cutime, cstime, after
   the comm is cut at its last `) `) plus whole MiB of `rchar`/`wchar` in the sibling `io` file; a file that cannot be
   opened is skipped, not fatal, in every awk (awk, gawk, mawk, busybox awk). Prints the sum, `0` when nothing matched.
5. `LineCut::take(chunk)` (machine-exec.ts:268-290) yields every complete line in the buffered bytes: the bytes before
   each `\n`, decoded UTF-8 lossily (each maximal invalid subsequence one U+FFFD, as node's `Buffer.toString` and
   `String::from_utf8_lossy` both do). A line (or the pending tail with no `\n` yet) longer than
   `EXEC_LINE_MAX_BYTES` (16 MiB) is cut at 16 MiB, moved back at most 3 bytes while the byte there is a UTF-8
   continuation byte (`0b10xxxxxx`), and each piece is its own line; a line of exactly 16 MiB is one line.
6. `LineCut::rest()` hands back the pending tail as one line and empties it; `None` when no byte is pending.
7. A line split across chunks, a character split across chunks, and `\r` before `\n` all survive: `"a\r\n\nb\r"`
   gives `"a\r"`, `""`, then `rest() = "b\r"`.

## Edge cases
- `turn_cut({idle 1000, deadline 2000}, 2000, 5000)` is the wall line `stopped after 0m 02s at the 0m turn limit; ...`;
  `(1999, 1000)` the idle line `stopped after 0m 02s with no output for 0m`; `(1999, 999)` is `None`;
  `({∞, ∞}, 1e12, 1e12)` is `None` (node, 2026-10-25).
- Activity from 0: `read(100,1000)` → quiet(1000)=1000; `read(104,2000)` → 2000 (4 < 5); `read(106,2000)` → 0
  (against the base at 1000); `read(50,3000)` → 1000 (a new base); `read(51,3000)` → 0 (floor is 1 when no time
  passed); `touch(500)` → quiet(3000)=2500; `hold(250)` → 2250 (node).
- `reads_work(∞, 1e12)` false, `(1000, 499)` false, `(1000, 500)` true, `(NaN, 1)` false.
- Lossy: bytes `61 ff fe 62 0a` → `"a\u{fffd}\u{fffd}b"`; `e2 82 0a` → one U+FFFD; `f0 9f 98 0a` → one; `ed a0 80 0a`
  → three; `c0 af 0a` → two (node).
- An empty chunk yields nothing and keeps the pending tail.

## Behaviour nobody wrote down
- The tree reading is only meaningful as a difference: `read` keeps no history but its base (rule 2 above).
- `touch` can move the clock backwards; the stream roads only ever touch with `now()`.

## Decisions
1. Limits are `f64` milliseconds because the exec verb hands both limits `Infinity`; times are `i64` ms epoch, cast to
   `f64` for the comparisons, as JS numbers are.
2. `TurnWaiting` is `Arc<dyn Fn() -> bool + Send + Sync>`.

## After the port
- `touch` with an earlier time moves the idle clock back; nothing calls it so today.
